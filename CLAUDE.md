# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Wisp: an original animated "dynamic notch" for Windows 10/11 (primary display only), written in Rust against raw Win32/GDI/GDI+/OLE plus the `windows` crate for media-session APIs. `.agents/skills/` holds local design-related agent skills (not app code, git-ignored). `.gitignore` also keeps `target/`, tester builds in `dist/` (only `dist/README-TESTER.txt` is tracked) out of the repo.

## Commands

Toolchain is `stable-x86_64-pc-windows-gnu`. If `cargo` is not on PATH, use `%USERPROFILE%\.cargo\bin\cargo.exe`.

```bash
cargo build --release                  # -> target/release/wisp.exe
cargo run --release -- --smoke-test    # headless-ish end-to-end check, writes smoke-result.txt, exits
cargo test                             # unit tests (COM layouts, drop target, tasks.rs, lyrics.rs parsing)
cargo test test_drop_target_ref_counting   # single test
```

The smoke test drives the real window: expand/collapse geometry (Now Playing `NP_W`×`EXP_H` = 460×196 / `CLOCK_W`×`COL_H` = 200×36 logical; the collapsed width grows to `COL_W` with `play_progress`), top-edge placement, shelf add/tab switch/clear, folder grouping, and clock↔playing mode transition. It writes `PASS`/`FAIL` to `smoke-result.txt` and has a 4-second timeout. Run it after behavioral changes; the result line format is also quoted in docs/BEHAVIOR.md.

Release build: `dist/Wisp-<version>-windows-x64.zip` (current: 0.1.6, tagged `v0.1.6`) holds `wisp.exe` (self-contained; it imports only Windows system DLLs, and Inter is embedded), `dist/README-TESTER.txt` and `assets/fonts/Inter-LICENSE.txt` (font install steps, SmartScreen, where data lives). Rebuild it by copying a fresh `target/release/wisp.exe`, the readme, `LICENSE` and `Inter-LICENSE.txt` into `dist/Wisp-<version>-windows-x64/` and zipping that folder; it is uploaded to a GitHub Release, never committed.


## Architecture

- **`src/main.rs`** (~1700 lines) holds nearly everything: hand-declared Win32 FFI (`extern "system"` blocks with custom `#[repr(C)]` structs rather than `windows` crate bindings), a hand-built COM `IDropTarget` vtable (`DropTarget`, `DROP_TARGET_VTBL`), one big `State` struct, the `paint` function, and the window procedure `procedure`, which matches on raw numeric message ids (`0x200` WM_MOUSEMOVE, `0x2a3` WM_MOUSELEAVE, etc.).
- **State ownership**: `State` is boxed in `main` and its pointer is stored in `GWLP_USERDATA` (`SetWindowLongPtrW(hwnd,-21,…)`); the window proc retrieves it from there.
- **Frame loop**: a worker thread calls `DwmFlush` and then `SendMessageW(hwnd, 0x8001)` once per compositor cycle (there is no fixed timer). Its pace is set by the UI thread at the end of each tick (`State::pace`): `PACE_MOTION` while the notch itself resizes or a page or layout spring runs (vsync-locked via `DwmFlush`, falling back to a timer if `DwmFlush` fails or returns in under 4 ms, as it does with the display off or the session locked, so the UI thread is never flooded and WM_PAINT is never starved); `PACE_AMBIENT` while only the waveform or a lyric glide moves, or the panel is open, a high-resolution sleep at the display rate (`refresh_interval()`), because `DwmFlush` costs noticeable CPU on some drivers; otherwise `PACE_IDLE`, about 10 ticks a second. Any input message sets `PACE_MOTION` at the top of `procedure`, waking an idle thread within 10 ms. Anything new that animates on its own must keep the pace at least ambient. The `0x8001` handler calls `State::advance(dt)`, which integrates the critically damped springs with exact elapsed-time math. It also polls the media channel, updates the clock, and, in smoke mode, runs the verification sequence.
- **Pages**: `TAB_MUSIC`, `TAB_CAL`, `TAB_TODO`, `TAB_POMO`, `TAB_SHELF`, `TAB_SETTINGS` (`TAB_COUNT`), drawn by `music_page`/`calendar_page`/`todo_page`/`pomo_page`/`shelf_page`/`settings_page` with page-local coordinates plus a `dx` from `page_left` and `page_mix`. Each page has its own width (`page_w`), and the window width springs via `panel_w` (`panel_w_now()`). Set `active_tab` directly; `advance` notices and starts the `tab_from`→`tab_to` transition on `tab_t`. Header targets come from `State::header_hit`, which both drawing and the mouse handlers use. `usable()` also waits until the page and size springs are within ~1.5 pt of their targets, which keeps page-local hit tests accurate without waiting out the settle.
- **To-do / Pomodoro**: their state machines and saving live in **`src/tasks.rs`** (Win32-free, unit tested). In `main.rs`, `todo_hit`/`pomo_hit` return hit codes (to-do 1000 field, 2000+i row, 3000+i delete; Pomodoro 4000+phase, 4010 Reset, 4011 Start, 4020/4021 length stepper −/+ (`POMO_STEP_*`; `Pomodoro::adjust` only between sessions, steps and ranges in `Phase::LIMITS`, saved as `Settings::pomo_minutes` and restored in `apply_settings`)) that are stored in `hover`/`pressed` and handled in `todo_click`/`pomo_click`. Typing comes through WM_CHAR (`0x102`) while `todo_editing`; WM_KILLFOCUS ends it. `Pomodoro::tick` runs every frame in the `0x8001` handler and triggers the completion alert. `timer_t` springs the collapsed live timer in and widens the collapsed notch (`col_w_now`). Header hit codes: tabs `0..TAB_COUNT`, 10 Clear, 12 breadcrumb (`breadcrumb_x()`). The gear tab is anchored to the right edge (`tab_x(TAB_SETTINGS)` uses `panel_w_now()`), and `clear_rect` sits just left of it. The switches and segmented control animate via `switch_t`/`seg_t` springs in `advance`, snapped at start-up by `snap_switches`; `autostart` caches the Run-key state. The notch has no context menu; quitting goes through **`src/tray.rs`** (notification-area icon drawn in code, `tray::CALLBACK` message, menu with only "Settings…" (opens the notch on `TAB_SETTINGS`, closing after 8 s via `alert_until`) and "Quit Wisp"; settings live on the Settings page: `SETTING_ROWS` maps rows to `tray::item` ids, `settings_hit` returns 5000+row, 5100+player, 5200 Quit, and `State::change_setting` applies them to `State::settings` (`src/settings.rs`: `Settings` load/save to `settings.txt`, plus `starts_with_windows`/`set_start_with_windows` on the HKCU Run key), re-added on the `TaskbarCreated` message, theme refresh on WM_SETTINGCHANGE). `tray.rs` reuses the crate-root FFI declarations.
- **Springs**: `progress`/`velocity` (expand/collapse), `play_progress` (collapsed clock ↔ playing mode), `tab_t` and `panel_w` (page switch and width morph; underdamped via `spring()`). Visuals are derived from these values (`reveal()`, `offset()`, `page_mix()`), and `usable()` gates interaction until things are essentially in place. A shelf card drag is cancelled only when the notch closes or the page changes, not by settling animations. Retargeting mid-motion keeps position and velocity. `reduced_motion` snaps springs to their targets; it is `Settings::follow_windows_animations && reduced_motion()` (SPI 0x1042), set by `State::apply_settings` and on WM_SETTINGCHANGE. The setting is off by default, so Wisp animates even on PCs with Windows animations disabled.
- **Custom messages**: `0x8001` frame tick; `0x8004`–`0x8007` are OLE drag enter/leave/drop/over, sent from `DropTarget` callbacks. The smoke test fakes drops by sending these same messages, so keep that path in sync with real drag-and-drop. `WM_DROPFILES` (`0x0233`) is a legacy fallback.
- **Rendering**: `paint` draws into a persistent full-size premultiplied BGRA DIB and presents it with `UpdateLayeredWindow`. Text goes through GDI `DrawTextW` with SF Pro Display fonts (`State.fonts`). Shapes and artwork go through **`src/render.rs`** `Renderer`, a thin GDI+ wrapper that loads `gdiplus.dll` dynamically via `GetProcAddress` (so the GNU build needs no GDI+ import lib). Its resources (graphics, brush, round-cap pen, path, artwork texture) are cached and reused. Icons (`icon_at`) are SF Symbols-style strokes on an 18 pt grid via `Renderer::stroke`/`stroke_bezier`/`stroke_round`/`stroke_ellipse`; prefer strokes over stacked fills for new glyphs. Avoid allocating per-frame surfaces. Every frame is redrawn, so drawing is cached where it is expensive: text goes through `cached_text` (GDI renders each distinct string, font, flags and box once into an 8-bit mask, which `blend_mask` blends in the DC's text color, honoring the clip box; entries unused for ~300 ticks are evicted), icons drawn with `icon_opt` go through `cached_icon` (masks per icon, variant and quarter-pixel phase, rendered on a small `IconCanvas` renderer), and `Renderer::artwork` keeps the rounded, scaled artwork for the current pixel size and phase (`ArtCache`). Call `DrawTextW` directly only for measuring. Because nothing but GDI+ fills and these blends touch the frame, the silhouette pass only processes the edge band; never draw GDI text straight into the frame DIB, since it clears alpha. All coordinates are logical pixels scaled by `State.px()`/`scale` (DPI). Layout constants (`COL_*`, `EXP_*`, `CARD_*`, `TRANSPORT_X`, `VOL_*`, `NP_LYRICS_H`) near the top of `main.rs` are shared by `paint` and the mouse hit tests, so change them there rather than adding literals.
- **Lyrics & volume**: `src/lyrics.rs` (LRCLIB worker via WinRT `HttpClient`: `/get` then looser searches via `clean_title`/`primary_artist`, then, when LRCLIB has no synced lyrics or is unreachable, NetEase (`netease`: search + `pick_song`, which accepts only exact title/artist/±3 s matches, then `netease_lyrics`, which drops credit lines; `serde_json` parses it); `http_client` disables cookies and the WinINet cache because NetEase's `NMTID` cookie makes its search return unrelated songs; `cargo test live_netease -- --ignored` hits it; `classify` treats any non-200/404 as `Failed` so overloads retry (about 10 min, `Status::Busy` sent after the first failed attempt) instead of reading as "not found"; disk cache in `%APPDATA%\Wisp\lyrics` checked before HTTP unless `Request::fresh`; LRC + minimal JSON parsing, unit tested; `cargo test live_lrclib -- --ignored` hits the real server) and `src/volume.rs` (the player's Core Audio sessions via `IAudioSessionManager2`, matched by process name to `Media::app`, on the UI thread). `State::request_lyrics` sends one request per track key; replies are matched by key in the `0x8001` handler. `play_pos` is the smoothed playback clock (advanced in `advance`, eased only toward `Media::pos_secs` samples that changed, since some players repeat stale positions); use it rather than sampled positions for anything time-synced. Lyrics on: `page_h(TAB_MUSIC)` becomes `NP_LYRICS_H` and `panel_h` springs the window height (DIB is `DIB_H` tall). `lyrics_t` morphs the layout, and `lyric_scroll` springs toward `lyric_target()`. Now Playing rows are anchored to the panel bottom (`panel_h-66` scrubber, `panel_h-26` controls). Collapsed lyrics: `collapsed_lyrics_active()` drives `clyric_t`. `lyric_w` springs to `lyric_w_target`, which is measured once per line in the `0x8001` handler, and is added into `col_w_now`. The line crossfade reuses `lyric_scroll`. Hit codes come from `music_hit`: 0..=2 transport, 4 retry lyrics (the NotFound/Failed message, via `retry_lyrics`), 5 lyrics, 6 mute, 7 volume slider (drag via `vol_drag` + capture), 8 scrubber, 9000+i lyric line.
- **Minimal mode**: `update_cover` (every `0x8001` tick, at most every 250 ms; off in smoke mode or when `Settings::minimal_when_covering` is off) runs `covers_window` on the normal closed footprint (`col_base_w()` × `COL_H`, never the shrunken size, so it can't oscillate). That walks the z-order with `GetTopWindow`/`GetWindow`, skipping own, invisible, iconic, cloaked and `WS_EX_TRANSPARENT` windows; the first one overlapping the footprint decides, and the desktop (`Progman`/`WorkerW`) means not covered. An app window then only counts if `screen_is_flat` (BitBlt from the screen DC of strips beside the notch, plus the area around the sliver when `covered && mini_t>0.99`; `is_flat` is unit tested) finds non-flat pixels, so empty title bars and tab strips never shrink it. It skips checks while expanded or showing a notification. `screen_is_flat` judges each area separately (pooling let a few letters in a strip vanish into the big area under the sliver, which made it ping-pong). `cover_step` (unit tested) decides: shrink after 2 content checks, grow back after 8 clear ones, and never within 3 s of the last switch (`cover_switched`). While covered, the footprint width is `cover_w`, the widest `col_base_w()` seen since shrinking. `mini_t` then blends `col_w_now`/`col_h_now` toward `MINI_W`×`MINI_H` before the notification blend, and `collapsed_fade()` fades collapsed content for both minimal mode and notifications.
- **Notifications**: `src/notify.rs` polls the Action Center's SQLite database (`wpndatabase.db`, read-only via a runtime-loaded `winsqlite3.dll` with a `sqlite!` macro like `render.rs`'s `gdiplus!`). It parses the toast XML (`parse_toast`, unit tested) and resolves the app's name and icon via `SHCreateItemInKnownFolder(FOLDERID_AppsFolder, AUMID)` + `IShellItemImageFactory`, then sends `Notice`s over a channel. `cargo test live_notifications -- --ignored --nocapture` reads the real database. In `main.rs`, `update_notices` (every `0x8001` tick) queues them and shows one at a time while collapsed. `notice_t` springs `col_w_now`/`col_h_now` to `NOTICE_W`×`NOTICE_H`, and `notice_fade()` fades the normal collapsed content. `notice_view` draws it; the icon goes through `Renderer::set_icon`/`icon` (a second PARGB image slot). While `notice_shown()`, WM_MOUSEMOVE holds it (`notice_hover`) instead of expanding, and a click (on WM_LBUTTONUP) runs `open_notice`. Smoke mode doesn't start the reader.
- **`src/media.rs`**: a background thread polls `GlobalSystemMediaTransportControlsSessionManager`, filters sessions to supported players via `media::app_key` (Spotify, Apple Music, Spotifast) and picks one with `media::choose` (unit tested): Windows' current session while playing, then the one already followed (`FOLLOWED`, so two playing apps do not flip), then any playing, then paused fallbacks; `media::set_player` (from the tray's "Music player" submenu, `Settings::player`) limits it to one app, and sends `Media` snapshots over an mpsc channel (`media::start()`). `seek`/`play_pause`/`next`/`prev` act on the followed session (`followed_session`), i.e. what is on screen.
- **Shelf**: `ShelfItem` with `children` for folder groups. It is persisted to `%APPDATA%\Wisp\shelf.txt` (`serialize_shelf`/`parse_shelf`/`load_shelf`; `tasks::data_path`/`write_data` hold the shared data dir). The `0x8001` handler saves when the serialized text differs from `shelf_saved`, so mutation sites need no save calls; smoke mode neither loads nor saves. Drag-out: when an internal card drag leaves the panel (or any drag in a folder view), `drag_out` builds a shell data object via `file_data_object` (`SHParseDisplayName` → `SHCreateDataObject` with the Desktop's empty ID list as parent; a null parent yields no CF_HDROP, covered by a unit test) and runs the modal `SHDoDragDrop`, offering copy/link only. `dragging_out` makes the `0x8004`–`0x8007` drop handlers ignore our own drag. `merge_items` handles drag-to-merge, `remove_folder_child` auto-ungroups when one child remains, and `active_folder` holds the folder view and breadcrumb.

## Constraints from the docs

- Keep it original: no forked app code. The calendar shows dates only (no agenda); never fabricate events.
- Fonts: SF Pro Display must be installed separately and is never bundled or redistributed (Apple license), including in tester builds. At startup `font_faces` uses SF Pro Display if `font_installed` finds it (GDI's `GetTextFaceW` reveals substitution); otherwise it loads the bundled Inter (`assets/fonts/Inter-Regular.ttf` and `Inter-Medium.ttf`, embedded with `include_bytes!`, SIL OFL, license in `assets/fonts/Inter-LICENSE.txt`) privately via `AddFontMemResourceEx`. Inter's Medium is its own GDI family, "Inter Medium", so the face is chosen per weight. Segoe UI is the last resort. Ship `Inter-LICENSE.txt` with any build. Medium is used for headings on purpose because the installed Semibold face is italic.
- Visual language is Apple macOS/iOS dark mode: label colors `WHITE`/`SECONDARY`/`TERTIARY`, system `RED` (calendar) and `BLUE` (drop targets), album-tinted waveform (`Renderer::tint`). No colored-tinted text, borders on cards, or bespoke accent colors.
- docs/BEHAVIOR.md documents behavior in detail; README.md is the GitHub overview. Update both when behavior changes.
